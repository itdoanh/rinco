## 1. Tổng quan — 3 Phân Vùng AI

RINCO tích hợp AI vào 3 phân vùng chức năng chính, tất cả giao tiếp qua NATS JetStream:

```
┌─────────────────────────────────────────────────────────────────┐
│  System Observability & eBPF Signals                           │
└────────────────────────────┬────────────────────────────────────┘
                             │
┌────────────────────────────┴────────────────────────────────────┐
│                  [ NATS JetStream ]                              │
└─────┬──────────────────────────┬─────────────────────────┬───────┘
      ▼                          ▼                         ▼
┌────────────────────┐  ┌─────────────────────┐  ┌──────────────────────┐
│  1. AI SRE         │  │  2. AI Predictive   │  │  3. AI Conversation  │
│  Code-LLM          │  │  XGBoost/LightGBM   │  │  vLLM + Whisper.cpp │
│  AST + Code RAG    │  │  Lead Scoring/pLTV  │  │  RAG Multi-tenant   │
│  Auto RCA + Hotfix │  │  FB CAPI Smart      │  │  STT + Summary      │
└────────────────────┘  └─────────────────────┘  └──────────────────────┘
```

**Nguyên tắc tích hợp:**
- **Zero-Trust:** Không AI agent nào có super-admin. Mỗi agent có permission set riêng (`AGENT_PERMISSIONS` enum).
- **Tenant-scoped:** Mọi cache key phải có `tenant_id` hash → chống PROMPTPEEK + cross-tenant leak.
- **Bounded:** Critical action (EXECUTE_SQL, RESTART_SERVICE) cần approval layer.
- **Observable:** Mọi AI inference đều có Prometheus metric + audit log.
- **RBAC cho AI:** Permission enum `READ_LOGS`, `READ_METRICS`, `READ_CODE`, `CREATE_PR`, `UPDATE_LEAD_SCORE`, `SEND_CAPI`, `TRANSCRIBE_AUDIO`, `EXECUTE_SQL` (require approval), `RESTART_SERVICE` (require 2-of-3 quorum).

## 2. AI SRE Engine — Root Cause Analysis + Auto-Hotfix

### 2.1. Mục tiêu

- Tự động **Root Cause Analysis** khi có lỗi production trong < 3 giây.
- Đề xuất **Hotfix Patch** + auto-create PR (confidence > 0.8).
- Phát hiện **code regression**, capacity planning.
- Phân tích stack trace + source code + Jaeger spans + ClickHouse logs.

### 2.2. Pipeline

```
[Error in Sentry/GlitchTip]
        ↓ webhook
[AI SRE Worker FastAPI]
        ↓
[1. Query ClickHouse logs by trace_id]      ← 100 entries
[2. Query Jaeger trace spans]                ← slowest operations
[3. Read source code (GitHub API at file:line)]
[4. AST Parsing → code structure]
[5. Code-LLM Analysis (DeepSeek-Coder-V2-Lite 16B AWQ)]
        ↓
[6. Generate RCA report JSON: root_cause, why, fix, diff, prevention, severity, confidence]
        ↓
[7. Send to Telegram/Slack with link]
        ↓
[Optional: confidence > 0.8 → Auto-create PR with patch]
```

### 2.3. Code-LLM Models

| Model | Size | Use case |
|-------|------|----------|
| **DeepSeek-Coder-V2-Lite** | 16B AWQ | Quick RCA, default |
| **DeepSeek-Coder-V2** | 236B | Deep code review |
| **Llama-3-70B-Code** | 70B | Alternative |
| **Codestral-22B** | 22B | Fast inference |

### 2.4. Auto-Hotfix PR

- Tạo branch `hotfix/{severity}-{uuid8}` từ `main`.
- Commit message: `fix({severity}): {root_cause}\n\nAuto-generated by AI SRE\n\nRoot cause: ...\nConfidence: 0.85`.
- PR title: `[AI SRE {severity}] {root_cause}`.
- Labels: `ai-generated`, `severity-p0/p1/p2/p3`, **`needs-review`** (luôn yêu cầu human review trước khi merge).
- Đăng ký GitHub bot signature: `AI SRE Bot <ai-sre@rinco.app>`.
- `_apply_fix` hiện đơn giản dùng string replace (`current.replace(original_code, fix_code)`); production cần AST-based transform.

## 5. Tenant-Scoped KV-Cache Hashing (PROMPTPEEK Defense)

### 5.1. Vấn đề — PROMPTPEEK Attack

Kẻ tấn công đo **first-token latency** để suy đoán prompt của tenant khác (cache hit = prompt tương tự tenant khác). KV-cache sharing giữa các tenant trong vLLM/SGLang có thể leak.

### 5.2. Defense 3 lớp

**Lớp 1 — Tenant-scoped cache key:**

```python
def compute_cache_key(prompt: str, tenant_id: str) -> str:
    prefix = prompt[:200]
    salted = f"{tenant_id}:{prefix}"
    return hashlib.sha256(salted.encode()).hexdigest()
```

Key Valkey: `ai:cache:{tenant_id}:{prefix_hash}` — cross-tenant cache hit = 0.

**Lớp 2 — First-token latency jitter:**

```python
async def anti_promptpeek_stream(response_generator):
    is_first = True
    async for token in response_generator:
        if is_first:
            jitter_ms = random.uniform(0, 50)
            await asyncio.sleep(jitter_ms / 1000.0)
            is_first = False
        yield token
```

Jitter std > 5ms, mean first-token vẫn < 200ms.

**Lớp 3 — Tenant routing per tier:**

- **Enterprise tier:** 1 vLLM instance riêng (dedicated).
- **Business tier:** Shared pool nhưng isolated prefix.
- **Starter tier:** Shared best-effort.

### 5.3. GPU Token Pool Admission Control

```python
class TokenPool:
    def __init__(self, total_tokens_per_sec=1000):
        self.tenants = {}  # tenant_id -> (rate, capacity, current, queue)

    def allow(self, tenant_id, tokens):
        rate, capacity, current, _ = self.tenants.get(tenant_id, (10, 100, 0, []))
        if current + tokens > capacity:
            return False
        self.tenants[tenant_id] = (rate, capacity, current + tokens, _)
        return True

    def release(self, tenant_id, tokens):
        # Decrease usage sau khi request xong
```

Per-tenant token bucket chống **tenant A spam → tenant B bị GPU starve**.

## 6. So sánh pgvector vs Qdrant

| Tiêu chí | pgvector + pgvectorscale | Qdrant |
|---------|------------------------|--------|
| **Kiến trúc Index** | HNSW / DiskANN | Dynamic HNSW + Quantization |
| **P99 Latency (< 10M)** | 5-15ms | 3-8ms |
| **Throughput (QPS)** | 300-500 | 1,500-2,500+ |
| **Multi-tenant filter** | `WHERE tenant_id` (SQL) | Payload filter (engine-native) |
| **Operational cost** | Thấp (reuse Postgres cluster) | Trung bình (cluster riêng) |
| **Cost optimization** | $0 (tận dụng Postgres) | Tối ưu RAM via On-Disk HNSW |
| **Best for** | < 10M vectors, ACID + vector | > 10M vectors, pure vector |
| **Vector dimension** | 1024 (BGE-M3) | 1024 (BGE-M3) |
| **Distance** | Cosine (`vector_cosine_ops`) | Cosine |

**Routing strategy:**

```python
def get_vector_store(tenant_id):
    if get_tenant_vector_count(tenant_id) < 10_000_000:
        return PGVectorStore(tenant_id=tenant_id)
    else:
        return QdrantStore(tenant_id=tenant_id)
```

**Hybrid search** (vector + BM25) dùng Meilisearch kết hợp re-ranking. **Re-ranking** dùng cross-encoder để cải thiện precision khi RAG context không relevant.

## 7. AI Operations (AIOps)

### 7.1. Anomaly Detection (Prophet + LSTM)

- **Prophet** cho time-series có seasonality (daily/weekly): `changepoint_prior_scale=0.05`, `interval_width=0.99`. Detect anomaly khi `actual > yhat_upper` hoặc `actual < yhat_lower`.
- **LSTM** cho complex patterns: 2-layer LSTM 50 units, Dropout 0.2, Dense 25, MSE loss. Detect qua **reconstruction error** > threshold (mặc định 0.1).
- Prometheus metric `ai_anomaly_detected_total{metric_name, severity}` (Counter).

### 7.2. Capacity Planner

Predict CPU/memory/storage 30 ngày tới bằng LSTM. Recommendation sizes XS/S/M/L/XL/2XL/4XL dựa trên:
- CPU > 80% → size up.
- Memory > 85% → size up.
- Storage > 90% → size up.
Output: `CapacityRecommendation(service, current_size, recommended_size, eta_days, reason, cost_impact)`.

### 7.3. AI SRE Workflow

```
[Alert fires] → [AI SRE Worker] → [Pull context: trace_id, logs, source code]
        ↓
[Code-LLM analysis] → [RCA report] → [Hotfix proposal if confident]
        ↓
[Notify on-call via Telegram] → [Human reviews PR → merges if good]
```

## 10. Edge Cases (≥ 30 AI scenarios)

- **AI-01 Hallucination:** fact-check service, giảm temperature, source citation.
- **AI-02 Prompt injection:** regex block, log security event.
- **AI-03 PROMPTPEEK timing attack:** jitter 0-50ms + tenant-scoped cache key.
- **AI-04 Model drift (AUC < threshold):** trigger retrain, rollback model version.
- **AI-05 GPU OOM:** fallback to CPU, scale down batch.
- **AI-06 Whisper hallucination (empty audio):** validate audio length > 0.
- **AI-07 RAG wrong context:** re-rank với cross-encoder, expand k.
- **AI-08 OpenAI rate limit:** switch self-hosted Llama-3, queue.
- **AI-09 Context > 32K tokens:** sliding window, summarize old.
- **AI-10 Function call fail:** retry 3×, fallback.
- **AI-11 GPU node fail:** vLLM migration sang node khác, retry ongoing requests.
- **AI-12 VRAM exhausted:** tăng offloading, giảm `--gpu-memory-utilization`.
- **AI-16 Tenant A leak qua cache key:** mandatory SHA256(tenant_id + prefix), audit.
- **AI-17 KV-cache leak PROMPTPEEK:** tenant-scoped prefix caching + jitter.
- **AI-18 Tenant A spam → tenant B starve:** token pool admission control.
- **AI-19 Data poisoning training:** per-tenant model isolation, anomaly detection.
- **AI-21 PII leak:** auto-redact trước LLM.
- **AI-22 Membership inference attack:** differential privacy, audit LLM outputs.
- **AI-25 Right-to-be-forgotten (GDPR):** mark training data deleted, retrain model.
- **AI-27 Token quota exceeded:** 429 + retry-after, force downgrade.
- **AI-30 API key leaked:** rotate, alert, rate limit.
- **AI-32 Training data drift (concept_drift > 0.3):** auto-retrain.
- **AI-34 Model bias (fairness < 0.7):** re-balance training data.
- **AI-35 Cold start tenant:** global model + warm up 100 samples.
- **AI-40 A/B test regression:** auto rollback.
- **AI-41 Audio > 4 giờ:** split by silence, chunk 30 phút.
